## 결정 사항과 이유
- 경로 가림은 "라우트 파라미터 이름에 `SENSITIVE_KEY` 적용" 방식: 목록 하나로 파라미터·쿼리·경로를 모두 덮기 위해. 라우트 전체 조사 결과 민감 경로 파라미터는 `{token}` 3곳(`reset-password/{token}`, `inquiry/{token}/message`, `inquiry/{token}/poll`)뿐. `{key}`(장바구니 상품id), `storage/{path}` 등은 비민감.
- `inquiry/{token}` 은 `app/Models/Inquiry.php` 에서 `Str::random(40)` 으로 만들고 `InquiryController::message/poll` 이 이것만으로 대화를 조회 → 자격 증명이므로 가림.
- 서명 URL·쿼리 토큰 사용처는 프로젝트에 없음(grep 확인). 그래도 `signature` 를 단일 목록에 예방적으로 추가.
- 라우팅 전 예외 대비로 메서드 무관 매칭(`matches($request, false)`) 폴백을 둠 (`RouteCollection::match` 는 405 시 예외라 쓰지 않음).
- 가린 표시는 기존 `scrub()` 과 같은 `[숨김]`.
- 쿼리는 `fullUrl()` 대신 원문 `QUERY_STRING` 사용 → 원래 순서 유지.
- 트레이스는 인자 전부 제거 (토큰뿐 아니라 비밀번호 인자도 차단, 위치 정보는 유지).
- 코드 변경은 커밋하지 않음 (지시: 커밋은 사람이 버튼으로). 병합 커밋만 지시대로 생성.
